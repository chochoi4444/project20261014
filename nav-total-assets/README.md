# 총자산 자동입력

분기마다 보유펀드별 기준가격대장(신탁재산명세부)에서 총자산을 찾아 대상 엑셀의 `총자산` 열에 옮겨 적던 작업을 자동화하는 브라우저 도구입니다.

- 사무수탁사마다 다른 양식(Excel `.xlsx`/`.xls`/`.csv`, 텍스트 PDF)을 읽습니다.
- 펀드명이 조금씩 달라도(띄어쓰기, `전문투자형사모`↔`일반사모`, `Ⅲ`↔`III`, `UP`↔`유나이티드파트너스` 등) 가장 가까운 장부를 고릅니다.
- 총자산은 `신탁재산총자산` 계정 → `순자산총액 + 부채` → `자산합계` 순으로 정하고, `총자산 = 순자산 + 부채`로 교차검증합니다.
- 원본 엑셀은 총자산 칸의 값만 바꾸고 서식·데이터 유효성·다른 시트는 그대로 둔 채 새 파일로 저장합니다.
- 모든 처리는 브라우저 안에서 일어나며 파일이 외부로 전송되지 않습니다.

## 사용법

1. 대상 엑셀(‘종목명’, ‘총자산’ 머리글이 있는 시트)을 1단계에 올립니다.
2. 펀드별 기준가격대장을 2단계에 여러 개(또는 폴더째) 올립니다.
3. 기준일을 확인합니다. 장부 기준일이 다르면 ‘검토’로 표시됩니다.
4. ‘자동’ 행은 바로 입력되고, ‘검토’ 행은 확인 후 체크합니다. 매칭이 틀리면 드롭다운에서 장부를 고르세요. 고른 매칭은 브라우저에 기억되고 JSON으로 내보내 팀과 나눌 수 있습니다.
5. **총자산 입력한 엑셀 저장**을 누르면 `원본이름_총자산입력.xlsx`가 만들어집니다. **매칭 결과 CSV**로 근거를 남길 수 있습니다.

## 파일 구성

| 경로 | 내용 |
| --- | --- |
| `src/app.html` | 도구 본체 (claude.ai 아티팩트로 배포되는 페이지, 라이브러리는 cdnjs에서 로드) |
| `build.mjs` | 라이브러리를 HTML 하나에 넣은 **오프라인판** 생성 |
| `tests/matching.test.mjs` | 펀드명 매칭 회귀 테스트 (`npm test`) |
| `tests/e2e.mjs` | 실제 장부로 끝까지 돌려 보는 점검 스크립트 (`npm run e2e`, 장부 파일은 저장소에 넣지 않음) |

## 오프라인판 만들기 (사내 PC용, 외부 접속 0건)

```bash
cd nav-total-assets
npm install
npm run build        # → dist/총자산자동입력_오프라인.html
```

만들어진 HTML 파일 하나를 사내 PC에서 더블클릭해 크롬/엣지로 열면 됩니다. 웹 폰트도 빠지므로 인터넷 연결이 전혀 필요 없습니다.

## 점검

### 펀드명 매칭 회귀 테스트

```bash
npm test
```

`tests/matching.test.mjs`가 `src/app.html`의 매칭 엔진 구역만 떼어 검사합니다(브라우저 불필요). 확인하는 내용:

- 표기가 달라도 맞는 종목을 1순위로 고르는지 — 법 개정 명칭(전문투자형사모→일반사모), 운용사 정식명·영문·띄어쓰기, 괄호 부가설명 생략, ‘호’·‘제’ 표기, 한글↔영문(블랙락↔BlackRock), 로마숫자(Ⅲ↔III), 클래스 표기, 운용사 약칭(머리글 운용사명으로 보강), 핵심 단어 변경(검토로 표시)
- 이름이 같아도 호수·종류가 다르면 후보가 되지 않는지 — 1호/2호, 89호1종/2종, 67호/67-1호, 3-1호/3-3호 등
- 맞는 장부가 빠졌을 때 번호만 다른 펀드에 붙지 않는지, 여러 장부가 1:1로 붙는지, 수동 매핑이 우선하는지

이 저장소는 **공개 저장소**라 테스트에는 가상의 펀드명을 씁니다. 실제 보유 종목으로 확인하려면 저장소 **밖**에 JSON을 두고 지정하세요.

```bash
MATCH_CASES=~/private/real-cases.json npm test
```

```json
{
  "targets": ["대상 엑셀의 종목명", "..."],
  "cases": [["대상 종목명", "장부에 적힌 펀드명", "장부 머리글 운용사명(선택)", ["auto", "review"]]]
}
```

### 실제 장부로 끝까지 돌려 보기

```bash
npm run build
TARGET=대상.xlsx LEDGERS=장부폴더 BASE_DATE=2026-09-30 npm run e2e
```

장부별 추출값, 매칭 결과, 저장된 파일 경로(`tests/output/`)를 출력합니다.

## 내부 사용 검토 요약

| 항목 | 판단 |
| --- | --- |
| 데이터 외부 전송 | 없음 (브라우저 메모리에서만 처리) |
| 설치·매크로·관리자 권한 | 필요 없음 |
| 외부 라이브러리 | SheetJS 0.18.5 (Apache-2.0), JSZip 3.10.1 (MIT), pdf.js 3.11.174 (Apache-2.0) — 오프라인판에 내장 가능 |
| 알려진 취약점 | SheetJS 0.18.5: CVE-2023-30533, CVE-2024-22363 (조작된 파일을 읽을 때). 내부 장부만 읽으므로 위험 낮음. 엄격한 기준이면 SheetJS 공식 0.20.x로 교체 후 빌드 |
| DRM 암호화 파일 | 읽을 수 없음 → 해제된 사본 사용 |
| 스캔(이미지) PDF | 읽을 수 없음 (OCR 미포함) → 수기 확인 |

## 기준가격대장에서 추가로 읽을 수 있는 값

샘플 3개 양식 모두 시산표 형식이라 총자산 외에 **순자산총액, 부채총액, 기준가격, 수익증권 좌수/원본, 기준일, 펀드코드**도 읽힙니다(양식 A는 설정일·해지일·수탁사·사무수탁사·보수율까지). 현재 엑셀에 입력하는 값은 총자산뿐이며, 나머지는 화면의 ‘장부별 추출값’과 CSV에 검증용으로만 나옵니다.
